● the philosophy

ABOUT

Arasaka is a desktop operating system that treats the OS as a verifiable, replaceable artifact instead of a permanent home. You work on it, not in it.

The idea

Normal desktops are mutable state machines. Every install, every update, every shell one-liner nudges the system somewhere it has never been before — and can never be again. Arasaka takes the opposite stance:

🗜

Immutable rootfs

The active system is a read-only squashfs, integrity-checked with dm-verity. There is no package manager in the image, so nothing can silently mutate the OS while it runs.

🔏

Signed from firmware up

Boot is a chain of signed Unified Kernel Images verified by Secure Boot. The LUKS2 root key is sealed to PCR 7 + PCR 11, so only this exact image can unlock this device.

🔄

Two slots, zero risk

Updates install into the inactive A/B slot, then the bootloader flips. On failure the previous slot boots automatically — rollback is a reboot, not a rescue mission.

Architecture

Boot chain

systemd-boot → signed UKI (kernel+initramfs+cmdline) → LUKS2 unlock via TPM2 → squashfs+verity rootfs mount. Hash failures refuse to boot; verity handles on-disk corruption.

Updates

RAUC writes the new slot, marks it pending, reboots, and the bootloader switches. Multi-source OTA pulls the bundle from redundant mirrors with automatic failover, so a dead source never strands a device.

Storage split

Small /boot, immutable /usr, and a dedicated /data partition holding the key bind-mounts (/home, /etc, /var) — your data survives every update.

Build pipeline

One CI build produces the OTA bundle and the live ISO from the same rootfs, each carrying sha256 and gpg signatures that the device verifies before applying.
